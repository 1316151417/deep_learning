🤔 为什么需要自动微分？

训练深度学习模型 = 最小化损失函数。这需要计算损失对每个参数的梯度。

想象一个 100 层的神经网络——如果手工求导，你需要推导成千上万个偏导数公式，任何一个错误都会导致训练失败。

自动微分解决了这个问题：你只需要写前向计算的代码，框架自动构建计算图，然后通过反向传播算出所有参数的梯度。

具体流程：附加梯度到变量 → 记录计算 → 调用 .backward() → 读取 .grad

1️⃣ 计算图 Computational Graph

定义

计算图是深度学习框架的核心数据结构：每个节点代表一次运算，每条边代表数据流动。

框架在你写 y = 2 * (x₁·x₂) 时，自动构建一张图：

x₁ ──┐
          ├── · ── ×2 ── y
x₂ ──┘

这张图记录了"哪些数据通过哪些操作产生了输出"，反向传播时沿图逆向追溯，逐节点应用链式法则。

2️⃣ 前向传播 & 反向传播

两步走

① 前向传播：从输入到输出，逐节点计算中间值和最终结果。同时偷偷记录每一步的运算类型和输入值。

② 反向传播："跟踪整个计算图，从输出端反向走到输入端，沿途用链式法则填充每个参数的偏导数。"

对于 y = 2·(x₁·x₂)：

  反向传播：∂y/∂(x₁x₂) = 2，然后 ∂(x₁x₂)/∂x₁ = x₂，最终 ∂y/∂x₁ = 2x₂

3️⃣ 基础用法（PyTorch 风格）

标准步骤

1
创建带梯度记录的张量：x = torch.arange(4.0, requires_grad=True)
2
定义计算（构建计算图）：y = 2 * torch.dot(x, x)
3
触发反向传播：y.backward()
4
读取梯度：x.grad

4️⃣ 梯度累加与清除

关键陷阱

⚠️ PyTorch 和 Paddle 默认累加梯度！每次调用 .backward()，梯度会累加到 .grad 上，而不是覆盖。

这是有意设计——方便处理梯度累积（多次小批次累积梯度后再更新参数）。

但如果你忘了手动清零（x.grad.zero_()），就会用错误的梯度更新模型！

框架默认行为清零方式
PyTorch累积 (累加)x.grad.zero_()
Paddle累积 (累加)x.clear_gradient()
MXNet覆盖无需手动清除
TensorFlow每次新建 tape重新建 GradientTape

5️⃣ 非标量的反向传播

问题

当 y 不是标量（是向量或矩阵）时，y.backward() 需要什么？

理论上，向量对向量的导数是一个矩阵（雅可比矩阵）。但在深度学习中，我们通常不需要完整的矩阵——只需要批量中每个样本偏导数之和。

框架的做法：要么自动求和再 backprop，要么要求你传入一个 gradient 参数指定"外层梯度"。

6️⃣ 分离计算图 Detach

场景

有时你希望把某个中间结果当作常数，阻断梯度向更早的节点传播。

典型场景：GAN 训练时冻结判别器；强化学习中的目标网络；或者你只是想"停掉"一部分梯度。

u = y.detach()（PyTorch）或 u = tf.stop_gradient(y)（TF）：值相同，但梯度不会流过 u 回到 y 的输入。

7️⃣ 控制流的梯度计算

超能力

自动微分的一个惊人特性：即使计算图中包含 Python 原生的 if/while/任意函数调用，也能正确计算梯度！

因为计算图是动态构建的——每次前向传播都会根据当前数据创建新的计算图，反向传播沿着这次实际走过的路径计算梯度。

示例函数（分段线性）：

def f(a):
    b = a * 2
    while b.norm() < 1000:
        b = b * 2
    if b.sum() > 0:
        c = b
    else:
        c = 100 * b
    return c

该函数是分段线性的：存在某个常数 k 使得 f(a) = k·a，因此梯度恒为 k。
