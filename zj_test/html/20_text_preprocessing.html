0 核心思想：把文本变成数字

神经网络只懂数值张量，而自然语言是一串变长的字符。要让模型处理文本，必须先把它预处理成固定规则下的整数序列。d2l 给出经典三步：

什么是 token？ 它是文本的最小处理单元。可以是「词」（the）也可以是「字符」（t）。本节默认按词分词，这也是后面语言模型的输入粒度。
为何要 <unk> 和 <pad>？ 词表装不下所有词（罕见词太多），所以低频词统一映射成 <unk>；句子长短不一无法堆叠成张量，所以用 <pad> 把短句补齐。它们是文本模型的两块「基石」。

1 读取语料：下载《时光机器》并清洗

d2l 用 H. G. Wells 的科幻小说 The Time Machine 作为玩具语料。先把非字母字符替换成空格、转小写，再按行存成字符串列表。一行清洗，全靠正则。

import requests, re
URL = "http://d2l-data.s3-accelerate.amazonaws.com/timemachine.txt"

def read_time_machine():
    text = requests.get(URL).text
    lines = text.splitlines()
    return [re.sub("[^A-Za-z]+", " ", line).strip().lower()
            for line in lines]

lines = read_time_machine()
# lines[0] == 'the time machine by h g wells'

2 ⭐ 分词：word 级 vs char 级

对每行文本调用 split()（word 级）或 list()（char 级），得到 token 列表。输入任意一句话，观察两种粒度的拆分结果。

def tokenize(lines, token="word"):
    if token == "word":
        return [line.split() for line in lines]
    if token == "char":
        return [list(line) for line in lines]

3 ⭐ 构建词表：频次排序 + 特殊 token

用 collections.Counter 统计所有 token 的频次，按频次降序排列，再在开头插入特殊 token。拖动 min_freq，看低频词被丢弃、词表如何收缩。

import collections

def count_corpus(tokens):
    return collections.Counter(tok for line in tokens for tok in line)

class Vocab:
    def __init__(self, tokens, min_freq=0, reserved_tokens=["<pad>"]):
        freqs = sorted(count_corpus(tokens).items(), key=lambda x: (x[1], x[0]), reverse=True)
        uniq = ["<unk>"] + reserved_tokens
        uniq += [w for w, c in freqs if c >= min_freq]
        self.idx_to_token = uniq
        self.token_to_idx = {w: i for i, w in enumerate(uniq)}

特殊 token 的索引是固定的：<unk>=0，<pad>=1。索引 0 永远表示「未知词」。查表时遇到词表里没有的词，统一返回 0——这就是 <unk> 的作用。

4 编码：token → index → tensor

词表建好，Vocab[token] 就能把任意 token 流转成整数索引流，再用 torch.tensor 包成张量。未登录词（OOV）自动落到 <unk>。

class Vocab:
    def __getitem__(self, tokens):
        if not isinstance(tokens, (list, tuple)):
            return self.token_to_idx.get(tokens, self.unk)   # 未登录 → 0
        return [self[t] for t in tokens]

    def to_tokens(self, indices):   # 反查: index → token
        return [self.idx_to_token[i] for i in indices]

idx = vocab["the time machine xyz".split()]
t = torch.tensor(idx)        # → tensor([ 2, 20, 51, 0])

编码是可逆的：vocab[token] 正向，vocab.to_tokens(idx) 逆向。模型输出一个整数，用 to_tokens 就能翻译回人类可读的词。这是后面文本生成的基础。

5 ⭐ Zipf 律：词频的幂律衰减

把所有词按频次降序排列，第 r 个词的频次 f(r) 近似满足 Zipf 律：

f(r) ∝ 1 / rα   （α ≈ 1，即 f(r) · r ≈ 常数）

在对数坐标下，log f 对 log r 是一条近似直线。这意味着：少数词占据绝大多数出现次数，大量词极为罕见（长尾）。切换坐标感受幂律。

Zipf 律的工程后果：长尾意味着绝大多数词出现极少。直接保留全部词，词表会爆炸；用 min_freq 截断后，这些罕见词全被映射成 <unk>。这就是上一节 min_freq 滑块的意义——也是子词分词（BPE）被发明的根本动机。

四条核心结论

结论说明
三步流水线 读取语料 → 分词 → 构建词表。任意原始文本都可用这条流水线转成模型可读的整数序列。
词表是有损的 min_freq 截断低频词 → <unk>。词表越大覆盖越好，但罕见词无论如何都学不好。
编码可逆 vocab[token] 正向编码，vocab.to_tokens(idx) 逆向解码。模型输出整数即可翻译回文本。
Zipf 律决定一切 词频 f(r) ∝ 1/r。长尾 → 截断 → <unk> → 信息丢失。这是子词分词（BPE）与大词表技术的根本动机。
下一步学什么？ 文本现在变成了一串整数。下一节会用这串整数训练一个语言模型——用过去几个词预测下一个词。这就要用到 §8.1 的自回归思想：n-gram / RNN 都建立在「token 序列 → 预测下一个 token」之上。
