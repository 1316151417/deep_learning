0 核心思想：把「句对」变成模型可读的小批量

语言模型（§8.3）处理的是单条文本流；而机器翻译是序列转换（sequence transduction）：输入一段源语言（这里英文），输出一段目标语言（这里中文）。数据集由成千上万个「源 / 目标」句对组成，两端都可能是变长的。

截断填充每句索引序列统一到 num_steps 长，记录 valid_len
与 §8.3 的根本区别：语言模型只有一条序列、一个词表；机器翻译有两条序列、两个词表。而且需要 <bos>（开始）和 <eos>（结束）告诉模型「何时开始 / 何时结束生成」——这是后面 Encoder-Decoder 的命脉。
特殊 token 的固定索引：<unk>=0，<pad>=1，<bos>=2，<eos>=3。索引 0 永远是「未知」，1 永远是「填充」。后面所有小批量的数字都按这套编码。

1 ⭐ 读取数据集：去掉每行末尾的署名信息

Tatoeba 的 cmn-eng 数据每行是三段制表符分隔：英文 \t 中文 \t 署名。第三段是 CC-BY 2.0 ... tatoeba.org #... 的版权署名，与翻译无关。read_data_nmt 用 parts[:2] 只保留前两段。

def read_data_nmt(fname=DATA_PATH):
    with open(fname, encoding="utf-8") as f:
        raw = f.read()
    lines = []
    for line in raw.split("\n"):
        parts = line.split("\t")
        if len(parts) >= 2:          # 过滤空行 / 异常行
            lines.append("\t".join(parts[:2]))   # 只留 英文\t中文
    return "\n".join(lines)

2 ⭐ 词元化：中文为何必须「字级」

d2l 原文对英-法数据，源和目标都按空格切词。法语有词边界（空格），没问题。但中文没有词边界——"你好。".split(" ") 会把整句当成一个 token！这正是 §9.5 练习 2 的问题。

def tokenize_nmt(text, num_examples=None):
    source, target = [], []
    for line in text.split("\n"):
        parts = line.split("\t")
        if len(parts) == 2:
            source.append(parts[0].split(" "))   # 英文: 词级
            target.append(list(parts[1]))        # 中文: 字级 ← 关键
    return source, target

词级切中文的灾难：32 028 句几乎每句都不一样，词级会让「目标词表」膨胀到 ~3 万个「整句 token」，且每个只出现 1~2 次——模型根本学不到任何泛化。字级把目标词表压到 ~3000 个常用汉字，每个字反复出现，才能有效学习。这就是代码里 target.append(list(parts[1])) 的原因。
现代做法：字级虽稳但语义粒度粗；工业级翻译用子词分词（BPE / WordPiece / SentencePiece），自动在「字」与「词」之间找平衡，对任何语言都适用——这也是练习 2 的「更优答案」。

3 双词表：源词表 / 目标词表

机器翻译要建两个词表：源端（英文词）和目标端（中文字）。都用 min_freq=2 把只出现 1 次的低频项并入 <unk>，并在开头预留 <pad><bos><eos>。注意源端最高频是 .（几乎每句结尾），目标端最高频是 。。

src_vocab = Vocab(source, min_freq=2, reserved_tokens=["<pad>", "<bos>", "<eos>"])
tgt_vocab = Vocab(target, min_freq=2, reserved_tokens=["<pad>", "<bos>", "<eos>"])
# |src_V| = 4802,  |tgt_V| = 3112

4 ⭐ 序列长度分布：源 vs 目标

5 ⭐ 截断填充 + 小批量

同一个小批里每条序列必须等长，才能堆成张量。流程：句末加 <eos> → 超过 num_steps 就截断，不足就用 <pad> 填充 → 记录有效长度 valid_len（非 pad 的个数）。

def truncate_pad(line, num_steps, padding_token):
    if len(line) > num_steps:
        return line[:num_steps]                       # 截断
    return line + [padding_token] * (num_steps - len(line))  # 填充

def build_array_nmt(lines, vocab, num_steps):
    lines = [vocab[l] + [vocab["<eos>"]] for l in lines]     # 末尾加 <eos>
    array = torch.tensor([truncate_pad(l, num_steps, vocab["<pad>"]) for l in lines])
    valid_len = (array != vocab["<pad>"]).type(torch.int32).sum(1)  # 非 pad 的个数
    return array, valid_len

四条核心结论

结论说明
数据是「句对」源 / 目标两条变长序列，需要两个词表，而非语言模型的一个。
中文必须字级中文无词边界，词级切分会把整句塌成 1 个 token、词表爆炸。字级（或子词）才是正解（§9.5 练习 2）。
截断填充统一长度句末加 <eos>，超长截断、不足填 <pad>，再用 valid_len 标记真实长度。
编码可回译验证索引 → to_tokens 还原文本。i can cook . ↔ 我会做饭。 完美对齐，证明管线无误。
这节产出的接口：load_data_nmt(batch_size, num_steps) → (data_iter, src_vocab, tgt_vocab)。每个小批是 (X, X_valid_len, Y, Y_valid_len) 四元组——这正是下一节 Encoder-Decoder（§9.6）和 Seq2Seq（§9.7）的训练输入。
