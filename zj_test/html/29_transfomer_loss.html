Transformer · 训练损失专题

训练时损失到底怎么算?为什么用「整数 id」当标签却不影响损失值

解码器吐出 (64, 10, 286) 的 logits,真值却只是 (64, 10) 的整数 token id。这页只讲两件事:① 这个损失一步步怎么算出来;② 为什么用自然数 id 当标签,而这个数字的大小根本不影响损失。下方有一个可点的「迷你词表损失计算器」把这两件事一次演给你看。

真实运行配置:batch=64、序列长 10、目标词表 V=286;首轮 per-token loss ≈ 0.505,训完 200 轮 ≈ 0.039。

1损失函数吃进去的三个东西

训练时 train() 里这一句 l = loss(Y_hat, Y, Yvl) 传进 MaskedSoftmaxCELoss 的就是下面三个张量。注意它们的形状各不相同——这恰恰是关键。

参数 1 · pred (Y_hat)
(64, 10, 286)

解码器输出的 logits。每个位置对词表里 286 个词各打一个分——一组未归一化的"概率猜测"。

参数 2 · label (Y)
(64, 10)

真值 token id。每个位置一个整数,表示"正确答案是词表第几号"。注意:比 pred 少了那一维 286。

参数 3 · valid_len (Yvl)
(64,)

每条目标句的有效长度。用来把后面 <pad> 填充位的损失屏蔽掉。

最反直觉的地方就在这:pred 每个位置是 286 个数(一条分布),label 每个位置是 1 个数(一个编号)。它们形状不同却能配对——因为交叉熵本来就是「一条分布 vs 一个正确编号」的运算,见第 3 节。

2四步算出损失:MaskedSoftmaxCELoss 逐行

class MaskedSoftmaxCELoss(nn.CrossEntropyLoss): def forward(self, pred, label, valid_len): weights = sequence_mask( torch.ones_like(label), valid_len) # ① (64,10) self.reduction = "none" # ② 关掉自动平均 unweighted = super().forward( pred.permute(0, 2, 1), label) # ③ (64,10) return (unweighted * weights).mean(dim=1) # ④ (64,)
1
weights = sequence_mask(ones, valid_len)
(64,10) · 0/1 掩码

先生成全 1 的 (64,10),再把每个样本超出有效长度的位置(即 <pad>)置 0。真 token = 1,padding = 0。

2
self.reduction = "none"
配置

CrossEntropyLoss 默认会把所有损失平均成一个标量。设 "none" 让它保留每个位置的损失,因为我们要自己先屏蔽 padding 再平均。

3
unweighted = CE(pred.permute(0,2,1), label)
(64,10) · 每位置一个 loss

permute 把 (64,10,286)→(64,286,10),让类别维 286 落在 dim 1(PyTorch 硬性约定)。然后每个位置算 −ln(softmax(logits)[label])。

4
(unweighted * weights).mean(dim=1)
(64,) · 每样本一个 loss

padding 位 ×0 归零,真 token 位保留;再沿序列维求平均,得到每个样本一个标量损失。

第 3 步就是整页的核心:label 这个整数只被当作下标,去 softmax(logits) 这条 286 长的概率向量里"挑出第 label 个分量",再取负对数。第 4 节会证明:这个整数的大小完全不影响结果,它只是个指针。

3交互:迷你词表损失计算器

把第 2 步放大到一个只有 6 个词的迷你词表(真实是 286 个)。每个词有一行 logits(模型对它的打分),softmax 把 logits 变成概率条。点任意一行把它设成"正确答案",损失会实时重算;再点「重新编号」打乱 id,你会看到损失纹丝不动。

4为什么「自然数 id」不影响损失值

反直觉感的根源是一个误解:损失函数从头到尾没有拿 token id 这个数去做任何算术,它只把它当"下标 / 指针"用。

  • 1
    id 是下标,不是数值。 label = 17 不表示"答案的值是 17 这么大",它只指向 softmax(logits) 这条向量里的第 17 个分量。整个过程是"查表",不是"加减乘除"——就像你用页码查字典,并不意味着你在对页码做数学。
  • 2
    换个编号,损失不变。 把词表的编号整体打乱(上节「重新编号」按钮):正确词的 id 从 2 变成 4,但它在概率向量里被取出的那个分量值没变,所以损失完全一样。证明:损失只取决于"指针 dereference 到的那个 logit",不取决于指针上印的数字。
  • 3
    这是分类问题,分类就该这样。 下一个词预测 = 从 286 个词里选 1 个 = 288 类分类。分类问题的标准目标就是"类别编号",标准损失就是交叉熵。这跟 ImageNet 用 0~999 的整数当标签一模一样——没人会把类别编号当成要回归的数值。
  • 4
    "比词向量"的直觉其实藏在输出层。 最后那个线性层 nn.Linear(32, 286) 的权重是 (286, 32),可看作每个词学了一个 32 维输出向量;logit_词w = 隐藏向量 · 词w的向量。所以模型确实在拿表示和每个词的向量比内积——只不过对全部 286 个词同时比,比出分数再 softmax,最后用 id 指出"该奖励哪一个"。

✓ 正确

把 id 当"类别下标" → 交叉熵

loss = −ln( 选中那个盒子的概率 )。重新编号 → 盒子换号,但被选中盒子的概率不变 → 损失不变。"好"是几号无所谓,只要 logits 和 label 对应上同一条。

✗ 错误

把 id 当"要回归的数值" → MSE

假如逼模型输出一个数去逼近 id 的数值:那"好"=2 和重新编号后"好"=4,目标就不同了,损失会变。这显然荒唐——同一个字没变,换个编号凭什么要学不同的数?这也正是不能用词向量 MSE 的根本原因。

一句话:输入侧用 id 查"输入词向量"(embedding),输出侧用 id 当"分类标签"去监督一个对所有词的打分。id 在两端都只起"指认是哪个词"的作用,从不作为数值参与运算——所以它是 0 还是 285,对损失毫无影响。

5记下这几条就够了

形状配对

(64,286,10) 的 logits 配 (64,10) 的 id:类别维被"吃掉",每个位置输出一个标量损失。

id 只下标

整数被用来从概率向量里挑分量,从不参与算术,所以它的大小不影响损失。

padding 归零

weights 把 <pad> 位的损失 ×0,只对真 token 求平均。

这是分类

选 1 个正确词 = V 类分类,交叉熵是标准做法;不是对向量做回归。

向量比较没丢

它被泛化进输出线性层:对所有词同时打分,再用 id 指出奖励谁。

编号可任意

重新编号词表,只要 logits 与 label 一同对应,损失完全不变。
