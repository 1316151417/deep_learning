2三种注意力：Q / K / V 分别从哪来

Transformer 里只有一种算子（缩放点积注意力），但它用三种不同的方式「接线」。看懂 Q/K/V 的来源，就看懂了三种子层的本质区别。

编码器自注意力

Q = X·K = X·V = X
padding mask

源句内部词与词互相看。Q=K=V=X，所以每个源词都能注意到整句。把 <pad> 位置 mask 掉。

解码器自注意力

Q = X·K = KV缓存·KV缓存
因果 mask 1..t

目标端内部交互。训练时用因果掩码：第 t 个位置只看 1..t，不能偷看未来的答案。预测时每步只喂 1 个新 token，K/V 来自不断增长的缓存。

编码器-解码器交叉注意力

Q = 解码端·K = memory·V = memory
padding mask

Q 来自解码器，K/V 来自编码器输出。这是「翻译时该看源句哪里」的地方——decoder 拿着自己的问题，去 memory 里挑相关的源信息。

只有交叉注意力的 K/V 来自另一侧。这是编码器信息流入解码器的唯一通道。其余两种注意力的 Q/K/V 都来自本侧序列。

4同一个解码器，两种用法

训练：teacher forcing

目标句已知，decoder 输入 = [<bos>] + Y[:-1]（目标右移一位），整句一次性送进去，每个位置同时预测。靠因果掩码保证「第 t 位看不到答案的未来部分」。

<bos>了他們<eos><pad><pad> 
dec_X = torch.cat([bos, Y[:, :-1]], 1)  # 整句
Y_hat, _ = net(X, dec_X, Xvl)            # 一次前向
整句并行 → 训练快；dec_valid_lens = 1..t 构造下三角可见区。

预测：自回归生成

没有真实目标句。从 <bos> 起，每步只喂 1 个 token，取最后一位 logits 的 argmax 作为下一个 token，再把它回填进输入，循环到 <eos>。

<bos>→下一个词↻ 
Y, state = net.decoder(dec_X, state)  # 每步1个token
dec_X = Y[:, -1:].argmax(dim=2)       # 回填
为避免每步重算历史，每层把已生成 token 的 K/V 存进 KV 缓存，逐步增长——见下一节。
