Transformer · 数值护栏专题

那些 ×√d、÷√d、LayerNorm ……「乘除一个特殊常数」的操作,到底在防什么?

读 29_transformer.py 时你会反复撞见一类操作:某处突然 × √d、某处 ÷ √d、某处又 LayerNorm 归一化。它们看似零散,其实是同一件事——控制数字的"幅度/方差",让 softmax 不饱和、梯度不消失、深层堆叠不漂移。这页按数据流(前向传播)顺序把它们串成一条线,每个关键处配一个可动手的小演示。

真实运行配置:num_hiddens = 32(= dmodel)、num_heads = 4、每个头维度 d = 8;于是 √dmodel ≈ 5.66、√dhead ≈ 2.83。

0一张图:三个"数值护栏",挡在数据流的三道关口

先把答案摆出来。Transformer 的前向通路里,有三处"乘除一个特殊常数"的操作,它们分别挡在三个关口,各防一种失败:

关口 ① · 输入端

嵌入放大

embedding(X) × √d_model

在 TransformerEncoder/Decoder.forward 第一行,embedding 一出来就乘 √32。

防:语义信号被位置编码淹没
关口 ② · 注意力核心

缩放点积

Q·Kᵀ ÷ √d

在 DotProductAttention 里,q、k 点积完立刻除以 √8。

防:softmax 饱和 → 梯度消失
关口 ③ · 每一层

层归一化

LayerNorm( x + 子层(x) )

每个 attention / FFN 外面都裹一层 AddNorm。

防:深层堆叠幅度漂移
统一主题:三件事看似无关,根因都是"数字太大或太小,网络就训不动"。所以下面三节(§1 嵌入放大 → §2 缩放点积 → §3 LayerNorm)严格按数据流顺序讲——这正好是你在代码里从上到下读到它们的顺序,也是信号在网络里流动的顺序。

1为什么 embedding 要 × √num_hiddens?

对应代码([29_transformer.py:151](../py/29_transformer.py#L151) 与 [:208](../py/29_transformer.py#L208)):

X = self.pos_encoding(self.embedding(X) * math.sqrt(self.num_hiddens)) # self.embedding = nn.Embedding(vocab_size, num_hiddens) # self.pos_encoding = PositionalEncoding(num_hiddens, dropout)

问题:词嵌入要和位置编码"相加",但两者量级不对等

embedding 查表得到的向量,接下来要和位置编码 PE 逐元素相加(X + self.P)。PE 是由 sin / cos 生成的、每个分量都被锁死在 [−1, 1] 之间、幅度 O(1)。而词嵌入向量:

  • ① 初始化时是 N(0,1),幅度 O(1);但训练过程中嵌入向量的幅度通常会缩小,远小于 1;
  • ② 即使不缩小,它也是"可学习、承载语义"的,而 PE 是"固定、承载位置"的。

如果直接相加、不加缩放:幅度偏小的 embedding 会被 O(1) 的 PE 盖过,X + P ≈ P——也就是说,模型拿到的输入几乎只剩位置信息,语义信息被稀释。

为什么偏偏是 √d_model 这个数? ① 它把 embedding 抬到与 PE 量级相当(而非淹没或被淹没),两者都能保留;② 这个 √d 和后面注意力里的 ÷√d(§2)是一对——一个在入口放大、一个在注意力里缩小,共同把信号方差维持在大致恒定。③ 出处:原论文 "Attention Is All You Need" 里输入嵌入与输出层共用同一矩阵,输出端做 softmax 需要嵌入幅度小、输入端又需要它够大,√d_model 正好平衡两端。

2为什么 Q·Kᵀ 要 ÷ √d?

对应代码([29_transformer.py:50](../py/29_transformer.py#L50)):

d = queries.shape[-1] # 每个头的维度,这里 = 8 scores = torch.bmm(queries, keys.transpose(1, 2)) / math.sqrt(d) self.attention_weights = masked_softmax(scores, valid_lens)

问题:维度越高,点积越大,softmax 就越"尖"

假设 q、k 的每个分量独立、均值 0、方差 1(经过线性层 + Xavier 初始化后近似成立)。点积 q·k = Σᵢ qᵢkᵢ 是 d 个乘积之和,于是:

Var(q·k) = Σᵢ Var(qᵢkᵢ) = Σᵢ (1·1) = d ⇒ std(q·k) = √d

也就是说,注意力分数的标准差随维度 d 线性增长到 √d。d=8 时 std≈2.83,d=512 时 std≈22.6。这些分数直接喂进 softmax,而 softmax 对"大的输入"极其敏感:

  • ① 分数一旦拉开 √d 的差距,softmax 输出就退化成几乎 one-hot——某个 key 拿走 ≈100% 的注意力,其余全是 0;
  • ② 而 softmax 的梯度是 (p − onehot);当 p 已经 ≈ onehot 时,梯度 ≈ 0;
  • ③ 于是反向传播传不回去,注意力学不动。这正是"梯度消失"的一种。
解法:除以 √d,把方差从 d 拉回 1(Var(score/√d) = d/d = 1)。分数回到 O(1),softmax 输出变得平滑、可微,梯度健康。这就是 "Scaled" Dot-Product Attention 里 "Scaled" 的全部含义。

3LayerNorm 到底是什么?为什么这里需要?

对应代码([29_transformer.py:112-119](../py/29_transformer.py#L112-L119))。每个 attention / FFN 子层外面都裹一层 AddNorm:

class AddNorm(nn.Module): def __init__(self, normalized_shape, dropout): ... self.ln = nn.LayerNorm(normalized_shape) # normalized_shape=[32] def forward(self, X, Y): return self.ln(self.dropout(Y) + X) # 残差相加,再层归一化

它做什么:对"每一个 token 的 d 个特征"做标准化

给一个 token 的特征向量 x ∈ ℝᵈ(这里 d=32),LayerNorm 独立地对这个向量做三步:

μ = mean(x) # 这个 token 自己的 d 个特征的均值 σ² = var(x) # 这个 token 自己的方差(注意:不是跨 batch!) x̂ = (x − μ) / √(σ² + ε) # 标准化到均值0、方差1;ε=1e-5 防除零 y = γ · x̂ + β # 再用"可学习"的缩放γ、平移β 重新整形

关键点(也是它和 BatchNorm 的根本区别):LayerNorm 是沿着"特征维"对单个 token 做的,完全不依赖 batch 里其他样本。所以——

为什么不选 BatchNorm? BatchNorm 沿 batch 维统计均值方差:① batch 大小一变统计量就变,推理时还得维护滑动平均;② 自回归解码时一次只喂 1 个 token,batch 维根本没法统计。LayerNorm 对每个 token 独立算,与 batch 无关,训练/推理行为一致,完美适配 NLP。
为什么这里必须归一化? Transformer 是 N 层相同结构堆起来的,每层都 x + 子层(x)。残差加法会让幅度层层累加、整体漂移(越来越大或越来越偏);子层输出也可能把分布推开。LayerNorm 在每次相加后把幅度"拉回"受控范围,再由 γ/β 重新整形成网络想要的样子——深层堆叠才稳得住、才训得动。
连 γ、β、ε 也都是"特殊值"! γ、β 是可学习的(初始 γ=1、β=0),给网络"反悔"归一化的自由;ε=1e-5 是个小常数,防止某个 token 所有特征都相等时 σ²=0 导致除零。一个 LayerNorm 里就藏了 3 类特殊值。

4还有哪些"乘除一个特殊值"的角落?

除了上面三处主角,代码里还散落着好几个特殊常数。它们无一例外,都是数值护栏——防溢出、防除零、防梯度爆炸、保持方差恒定。逐个点名:

masked_softmax · 第 31 行
−1e6

把 padding 位置在 softmax 之前置成一个巨大的负数。这样 exp(−1e6) ≈ 0,padding 位概率精确归零。为什么不用 0?因为 exp(0)=1,padding 会分到正概率;为什么不用 −∞?会产生 NaN。−1e6 = 安全的"负无穷"。

PositionalEncoding · 第 92-93 行
10000

位置编码的频率底数。1 / 10000^(2i/d) 让不同维度有从 2π 到 2π·10000 的多尺度波长:高频维区分相邻位置,低频维区分远距离位置。10000 够大,长序列也能编码出可区分的位置。

train · 第 247 行
clip_grad_norm_(…, 1)

梯度裁剪的上限。把所有参数梯度的整体 L2 范数限制在 1 以内。一旦某步梯度爆炸(范数>1),就等比缩放回去。防的是训练瞬间崩盘——和 RNN 里一模一样的招。

xavier · 第 227-229 行
方差 2/(fan_in+fan_out)

Xavier 初始化给权重填入这个特定方差的随机数。它正是为"让每一层输出的方差≈输入方差"算出来的最优缩放——本质就是乘上一个 √(2/(in+out)) 的特殊因子。和 §1~§3 是同一个"控方差"主题。

Dropout · 全局 dropout=0.1
× 1/(1−p)

Dropout 随机置零 10% 的激活后,会把剩下的乘以 1/0.9 ≈ 1.11。这个放大是为了让"开/关 dropout"时的期望幅度不变——又一个保方差的常数。(代码里用 nn.Dropout 自动处理。)

LayerNorm 内部
ε = 1e-5

标准化分母里的 √(σ² + 1e-5)。当某 token 所有特征几乎相等时 σ²≈0,没有 ε 就会除零产生 inf/NaN。一个小常数兜底,和上面的 −1e6 是同一种"防数值灾难"的思路。

AddNorm · 第 119 行
残差 + X

严格说不是"常数",但 dropout(Y) + X 里的 + 是残差连接本身:让梯度能直通浅层,解决深层梯度消失。LayerNorm 负责控幅度,残差负责通梯度,二者搭档(所以叫 AddNorm)。

softmax 数值稳定(Python 侧未显式写)
− max(x)

F.softmax 内部会先减去最大值再 exp,防 exp(大数) 上溢。masked_softmax 用的 −1e6 其实就是手工版的"压住不该赢的项"——同一套稳定化思路。

一句话总结:Transformer 里那些看着奇怪的"乘除一个特殊常数",没有一个是玄学——它们是为了让数字保持在网络能正常学习的尺度。理解了"控幅度/控方差"这一根主线,你就能自己推导出:哪里数字会变大(→缩小它)、哪里会漂移(→归一化它)、哪里可能除零/溢出(→加兜底常数)。
